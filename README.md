# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Типы данных

Все типы и интерфейсы приложения объявлены в файле `src/types/index.ts`.

### Интерфейсы данных предметной области

`IProduct` — описывает товар, который приходит с сервера и хранится в каталоге и корзине.

```ts
interface IProduct {
    id: string;          // уникальный идентификатор товара
    description: string; // подробное описание
    image: string;       // относительный путь к изображению
    title: string;       // название
    category: string;    // категория товара
    price: number | null; // цена; null означает, что товар недоступен к покупке
}
```

`TPayment` — допустимые способы оплаты. Пустая строка соответствует состоянию «способ оплаты ещё не выбран», в котором покупатель находится до начала оформления заказа.

```ts
type TPayment = 'card' | 'cash' | '';
```

`IBuyer` — данные покупателя, которые он указывает при оформлении заказа.

```ts
interface IBuyer {
    payment: TPayment; // выбранный способ оплаты
    email: string;     // электронная почта
    phone: string;     // телефон
    address: string;   // адрес доставки
}
```

`TValidationErrors` — результат проверки данных покупателя. Ключ соответствует полю `IBuyer`, значение — текст ошибки. Поля, прошедшие проверку, в объекте отсутствуют, поэтому пустой объект означает полную валидность данных.

```ts
type TValidationErrors = Partial<Record<keyof IBuyer, string>>;
```

### Интерфейсы моделей данных

Для каждого класса-модели объявлен отдельный интерфейс экземпляра, который класс реализует через `implements`: `ICatalog`, `ICart`, `IBuyerModel`. Интерфейсы фиксируют публичный контракт моделей и позволяют компоненту, использующему модель, зависеть от интерфейса, а не от конкретной реализации.

### Типы обмена данными с сервером

`IApiList<T>` — обобщённая форма списочного ответа сервера. Каталог товаров описывается как `IApiList<IProduct>`.

```ts
interface IApiList<T> {
    total: number; // общее количество элементов
    items: T[];    // массив элементов
}
```

`IOrder` — тело запроса на оформление заказа. Расширяет `IBuyer`, добавляя сумму заказа и список идентификаторов выбранных товаров.

```ts
interface IOrder extends IBuyer {
    total: number;    // итоговая сумма заказа
    items: string[];  // массив идентификаторов товаров
}
```

`IOrderResult` — ответ сервера на успешное оформление заказа.

```ts
interface IOrderResult {
    id: string;    // идентификатор созданного заказа
    total: number; // подтвержденная сервером сумма
}
```

## Модели данных

Классы слоя «Модели» отвечают исключительно за хранение данных и операции над ними. Они не содержат инструментов отображения, не обращаются к серверу и не зависят друг от друга, благодаря чему могут использоваться и проверяться независимо от остального приложения. Файлы классов расположены в папке `src/components/Models/`.

### Класс Catalog

Отвечает за хранение каталога товаров, доступных к покупке, и за товар, выбранный пользователем для подробного просмотра. Реализует интерфейс `ICatalog`.

Конструктор не принимает параметров.

Поля класса:
`items: IProduct[]` — массив всех товаров каталога. При создании экземпляра инициализируется пустым массивом.
`selectedItem: IProduct | null` — товар, выбранный для подробного отображения. Инициализируется значением `null`, которое соответствует состоянию «товар не выбран».

Методы класса:
`setItems(items: IProduct[]): void` — сохраняет переданный массив товаров в поле класса, замещая ранее сохранённые данные.
`getItems(): IProduct[]` — возвращает массив всех товаров каталога.
`getItemById(id: string): IProduct | undefined` — выполняет поиск товара по идентификатору. Возвращает найденный товар либо `undefined`, если товар с таким идентификатором в каталоге отсутствует.
`setSelectedItem(item: IProduct): void` — сохраняет переданный товар как выбранный для подробного отображения.
`getSelectedItem(): IProduct | null` — возвращает выбранный товар либо `null`, если товар не был выбран.

### Класс Cart

Отвечает за хранение товаров, которые покупатель выбрал для покупки, и за расчёт итоговых показателей корзины. Реализует интерфейс `ICart`.

Конструктор не принимает параметров.

Поля класса:
`items: IProduct[]` — массив товаров, добавленных в корзину. При создании экземпляра инициализируется пустым массивом.

Методы класса:
`getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине.
`addItem(item: IProduct): void` — добавляет переданный товар в конец массива корзины.
`removeItem(item: IProduct): void` — удаляет товар из корзины. Сравнение выполняется по идентификатору товара, а не по ссылке на объект.
`clear(): void` — полностью очищает корзину, присваивая полю пустой массив.
`getTotalPrice(): number` — возвращает суммарную стоимость товаров в корзине. Товары со значением `price`, равным `null`, учитываются в сумме как нулевые.
`getItemsCount(): number` — возвращает количество товаров в корзине.
`hasItem(id: string): boolean` — проверяет наличие товара в корзине по его идентификатору.

### Класс Buyer

Отвечает за хранение данных покупателя и их проверку на корректность. Реализует интерфейс `IBuyerModel`.

Конструктор не принимает параметров.

Поля класса:
`payment: TPayment` — выбранный способ оплаты. Инициализируется пустой строкой.
`email: string` — электронная почта покупателя. Инициализируется пустой строкой.
`phone: string` — телефон покупателя. Инициализируется пустой строкой.
`address: string` — адрес доставки. Инициализируется пустой строкой.

Методы класса:
`setData(data: Partial<IBuyer>): void` — сохраняет данные покупателя. Принимает объект, в котором все поля необязательны, и обновляет только те поля, которые были переданы. Значения остальных полей при этом сохраняются, что позволяет записывать данные по одному полю за раз — например, только адрес или только способ оплаты.
`getData(): IBuyer` — возвращает новый объект со всеми данными покупателя. Возврат копии, а не ссылки на модель, исключает изменение хранимых данных в обход метода `setData`.
`clear(): void` — очищает все данные покупателя, возвращая полям исходные пустые значения.
`validate(): TValidationErrors` — проверяет данные покупателя и возвращает объект ошибок. Поле считается валидным, если его значение непустое. Для каждого непройденного поля в объект добавляется ключ с текстом ошибки; валидные поля в объекте отсутствуют. Пустой объект означает, что все данные заполнены корректно. Тексты сообщений об ошибках вынесены в константу `validationErrors` в файле `src/utils/constants.ts`.

## Слой коммуникации

Классы этого слоя отвечают за обмен данными с сервером. Файлы классов расположены в папке `src/components/Communication/`.

### Класс LarekApi

Отвечает за взаимодействие приложения с API сервера «Веб-ларёк»: получение каталога товаров и отправку оформленного заказа.

Класс не наследуется от базового класса `Api`, а использует его через композицию: экземпляр клиента передаётся в конструктор и сохраняется в защищённом поле. Тип поля и параметра конструктора — интерфейс `IApi`, а не конкретный класс, что обеспечивает инверсию зависимостей: класс зависит от контракта, а не от реализации, и клиент может быть заменён любым объектом, соответствующим `IApi`.

Конструктор:
`constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`, и сохраняет его для последующего выполнения запросов.

Поля класса:
`api: IApi` — экземпляр клиента для выполнения HTTP-запросов.

Методы класса:
`getProducts(): Promise<IApiList<IProduct>>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, содержащим общее количество товаров и массив товаров каталога.
`postOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order/`, передавая в теле запроса данные покупателя, сумму заказа и массив идентификаторов выбранных товаров. Возвращает промис с объектом, подтверждающим оформление заказа.

Базовый адрес сервера хранится в константе `API_URL` в файле `src/utils/constants.ts` и формируется из переменной окружения `VITE_API_ORIGIN`. Относительные пути эндпоинтов вынесены в константы `PRODUCTS_ENDPOINT` и `ORDER_ENDPOINT` того же файла.
