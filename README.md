# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`  
`setText(element: HTMLElement | null, value: unknown): void` - утилитарный метод для установки текстового содержимого элемента.  
`setDisabled(element: HTMLElement | null, state: boolean): void` - утилитарный метод для блокировки и разблокировки кнопок и полей ввода.  
`toggleClass(element: HTMLElement | null, className: string, state: boolean): void` - утилитарный метод для добавления и удаления CSS-класса у элемента.

#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Типы данных

Все типы и интерфейсы приложения объявлены в файле `src/types/index.ts`.

### Интерфейсы данных предметной области

`IProduct` — описывает товар, который приходит с сервера и хранится в каталоге и корзине.

```ts
interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

`TPayment` — допустимые способы оплаты. Пустая строка соответствует состоянию «способ оплаты не выбран».

```ts
type TPayment = 'card' | 'cash' | '';
```

`IBuyer` — данные покупателя, указываемые при оформлении заказа.

```ts
interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}
```

`TValidationErrors` — результат проверки данных покупателя. Ключ соответствует полю `IBuyer`, значение — текст ошибки. Валидные поля в объекте отсутствуют.

```ts
type TValidationErrors = Partial<Record<keyof IBuyer, string>>;
```

### Интерфейсы моделей данных

Для каждого класса-модели объявлен отдельный интерфейс экземпляра, который класс реализует через `implements`: `ICatalog`, `ICart`, `IBuyerModel`.

### Типы обмена данными с сервером

`IApiList<T>` — обобщённая форма списочного ответа сервера. Каталог товаров описывается как `IApiList<IProduct>`.

```ts
interface IApiList<T> {
    total: number;
    items: T[];
}
```

`IOrder` — тело запроса на оформление заказа.

```ts
interface IOrder extends IBuyer {
    total: number;
    items: string[];
}
```

`IOrderResult` — ответ сервера на успешное оформление заказа.

```ts
interface IOrderResult {
    id: string;
    total: number;
}
```

### Типы данных компонентов представления

Каждый компонент представления параметризован типом данных, которые принимает его метод `render`.

`TCardBase` — поля, общие для всех трёх видов карточек.

```ts
type TCardBase = Pick<IProduct, 'title' | 'price'>;

type TCardCatalog = TCardBase & Pick<IProduct, 'category' | 'image'>;

type TCardPreview = TCardCatalog & {
    description: string;
    buttonLabel: string;
    buttonDisabled: boolean;
};

type TCardBasket = TCardBase & {
    index: number;
};

type THeader = {
    counter: number;
};

type TGallery = {
    catalog: HTMLElement[];
};

type TModal = {
    content: HTMLElement;
};

type TBasket = {
    items: HTMLElement[];
    total: number;
    buttonDisabled: boolean;
};

type TSuccess = {
    total: number;
};
```

`TFormState` — общее состояние формы. Типы конкретных форм собираются из него и полей `IBuyer`.

```ts
type TFormState = {
    valid: boolean;
    errors: string;
};

type TOrderForm = TFormState & Pick<IBuyer, 'payment' | 'address'>;

type TContactsForm = TFormState & Pick<IBuyer, 'email' | 'phone'>;
```

### Типы данных событий

```ts
type TCardEvent = {
    id: string;
};

type TPaymentEvent = {
    payment: TPayment;
};

type TInputEvent = {
    field: keyof IBuyer;
    value: string;
};
```

## Модели данных

Классы слоя «Модели» отвечают за хранение данных и операции над ними. Они не содержат инструментов отображения, не обращаются к серверу и не зависят друг от друга. При любом изменении хранимых данных модель генерирует событие через брокер, передаваемый в конструктор.

Файлы классов расположены в папке `src/components/Models/`.

### Класс Catalog

Отвечает за хранение каталога товаров и товара, выбранного для подробного просмотра. Реализует интерфейс `ICatalog`.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`items: IProduct[]` — массив всех товаров каталога.  
`selectedItem: IProduct | null` — товар, выбранный для подробного отображения.  
`events: IEvents` — брокер событий.

Методы класса:  
`setItems(items: IProduct[]): void` — сохраняет переданный массив товаров и генерирует событие `catalog:changed`.  
`getItems(): IProduct[]` — возвращает массив всех товаров каталога.  
`getItemById(id: string): IProduct | undefined` — возвращает товар по идентификатору либо `undefined`.  
`setSelectedItem(item: IProduct): void` — сохраняет товар для подробного отображения и генерирует событие `catalog:selected`.  
`getSelectedItem(): IProduct | null` — возвращает выбранный товар либо `null`.

### Класс Cart

Отвечает за хранение товаров, выбранных покупателем, и расчёт итоговых показателей корзины. Реализует интерфейс `ICart`.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`items: IProduct[]` — массив товаров в корзине.  
`events: IEvents` — брокер событий.

Методы класса:  
`getItems(): IProduct[]` — возвращает товары корзины.  
`addItem(item: IProduct): void` — добавляет товар и генерирует событие `cart:changed`.  
`removeItem(item: IProduct): void` — удаляет товар по идентификатору и генерирует событие `cart:changed`.  
`clear(): void` — очищает корзину и генерирует событие `cart:changed`.  
`getTotalPrice(): number` — возвращает суммарную стоимость товаров. Товары со значением `price`, равным `null`, учитываются как нулевые.  
`getItemsCount(): number` — возвращает количество товаров.  
`hasItem(id: string): boolean` — проверяет наличие товара по идентификатору.

### Класс Buyer

Отвечает за хранение данных покупателя и их проверку. Реализует интерфейс `IBuyerModel`.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий.

Поля класса:  
`payment: TPayment` — выбранный способ оплаты.  
`email: string` — электронная почта покупателя.  
`phone: string` — телефон покупателя.  
`address: string` — адрес доставки.  
`events: IEvents` — брокер событий.

Методы класса:  
`setData(data: Partial<IBuyer>): void` — обновляет только переданные поля, сохраняя значения остальных, и генерирует событие `buyer:changed`.  
`getData(): IBuyer` — возвращает новый объект со всеми данными покупателя.  
`clear(): void` — очищает все данные и генерирует событие `buyer:changed`.  
`validate(): TValidationErrors` — возвращает объект ошибок. Поле валидно, если непустое; валидные поля в объекте отсутствуют. Тексты сообщений вынесены в константу `validationErrors`.

## Слой коммуникации

Классы этого слоя отвечают за обмен данными с сервером. Файлы расположены в папке `src/components/Communication/`.

### Класс LarekApi

Отвечает за взаимодействие приложения с API сервера «Веб-ларёк». Использует класс `Api` через композицию: экземпляр передаётся в конструктор с типом интерфейса `IApi`.

Конструктор:  
`constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`.

Поля класса:  
`api: IApi` — экземпляр клиента для выполнения HTTP-запросов.

Методы класса:  
`getProducts(): Promise<IApiList<IProduct>>` — GET-запрос на эндпоинт `/product/`, возвращает объект с массивом товаров каталога.  
`postOrder(order: IOrder): Promise<IOrderResult>` — POST-запрос на эндпоинт `/order/` с данными заказа, возвращает объект подтверждения.

Базовый адрес сервера хранится в константе `API_URL`, пути эндпоинтов — в константах `PRODUCTS_ENDPOINT` и `ORDER_ENDPOINT`.

## Классы слоя представления

Классы слоя «Представление» отвечают за отображение данных в интерфейсе. Все они наследуются от базового класса `Component`. Элементы разметки находятся в конструкторе и сохраняются в полях класса, слушатели устанавливаются один раз в конструкторе. Классы не хранят отображаемых данных и не содержат логики: о действиях пользователя они сообщают событием через брокер либо вызовом колбэка, полученного в конструкторе.

Файлы классов расположены в папке `src/components/View/`.

Иерархия наследования:

```
Component
├── Header
├── Gallery
├── Modal
├── Basket
├── Success
├── Card (абстрактный)
│   ├── CardBasket
│   └── ProductCard (абстрактный)
│       ├── CardCatalog
│       └── CardPreview
└── Form (абстрактный)
    ├── OrderForm
    └── ContactsForm
```

### Класс Header

Отвечает за отображение шапки страницы: счётчика товаров в корзине и кнопки её открытия.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент шапки и брокер событий, находит элементы и устанавливает слушатель клика на кнопку.

Поля класса:  
`basketButton: HTMLButtonElement` — кнопка открытия корзины.  
`counterElement: HTMLElement` — элемент со счётчиком товаров.  
`events: IEvents` — брокер событий.

Сеттеры:  
`set counter(value: number)` — выводит количество товаров в корзине.

### Класс Gallery

Отвечает за отображение каталога товаров на главной странице.

Конструктор:  
`constructor(container: HTMLElement)` — принимает корневой элемент галереи.

Сеттеры:  
`set catalog(items: HTMLElement[])` — заменяет содержимое галереи переданным массивом разметки карточек.

### Класс Modal

Отвечает за отображение модального окна. Наследников не имеет: разметка внутри окна — самостоятельные компоненты, передаваемые снаружи.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент окна и брокер событий, находит элементы и устанавливает слушатели на кнопку закрытия и на контейнер.

Поля класса:  
`closeButton: HTMLButtonElement` — кнопка закрытия окна.  
`contentElement: HTMLElement` — контейнер содержимого окна.  
`events: IEvents` — брокер событий.

Сеттеры:  
`set content(value: HTMLElement)` — помещает переданную разметку в контейнер содержимого.

Методы класса:  
`open(): void` — показывает окно, добавляя корневому элементу модификатор `modal_active`.  
`close(): void` — скрывает окно и очищает контейнер содержимого.

### Класс Card

Абстрактный базовый класс карточек товара. Содержит поля и сеттеры, общие для всех трёх шаблонов карточек.

Конструктор:  
`protected constructor(container: HTMLElement)` — принимает корневой элемент карточки, находит элементы названия и цены.

Поля класса:  
`titleElement: HTMLElement` — элемент с названием товара.  
`priceElement: HTMLElement` — элемент с ценой товара.

Сеттеры:  
`set title(value: string)` — выводит название товара.  
`set price(value: number | null)` — выводит цену с указанием валюты; для товаров без цены выводится «Бесценно».

### Класс ProductCard

Абстрактный класс, наследуется от `Card`. Содержит поля и сеттеры, общие для карточки каталога и подробной карточки.

Конструктор:  
`protected constructor(container: HTMLElement)` — принимает корневой элемент карточки, находит элементы категории и изображения.

Поля класса:  
`categoryElement: HTMLElement` — элемент с названием категории.  
`imageElement: HTMLImageElement` — изображение товара.

Сеттеры:  
`set category(value: string)` — выводит название категории и переключает модификатор фона согласно объекту `categoryMap`.  
`set image(value: string)` — устанавливает изображение, формируя полный адрес из константы `CDN_URL` и пути из данных товара.

### Класс CardCatalog

Отвечает за отображение карточки товара в галерее. Наследуется от `ProductCard`.

Конструктор:  
`constructor(container: HTMLElement, onClick: () => void)` — принимает корневой элемент, полученный клонированием шаблона `#card-catalog`, и функцию-обработчик клика, которая устанавливается на контейнер.

Собственных полей и сеттеров класс не имеет.

### Класс CardPreview

Отвечает за отображение подробной карточки товара в модальном окне. Наследуется от `ProductCard`.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент, полученный клонированием шаблона `#card-preview`, и брокер событий, находит элементы и устанавливает слушатель клика на кнопку действия.

Поля класса:  
`descriptionElement: HTMLElement` — элемент с описанием товара.  
`actionButton: HTMLButtonElement` — кнопка покупки или удаления из корзины.  
`events: IEvents` — брокер событий.

Сеттеры:  
`set description(value: string)` — выводит описание товара.  
`set buttonLabel(value: string)` — задаёт надпись на кнопке действия.  
`set buttonDisabled(state: boolean)` — блокирует или разблокирует кнопку действия.

### Класс CardBasket

Отвечает за отображение строки товара в корзине. Наследуется от `Card`.

Конструктор:

### Класс Basket

## Презентер

Логика приложения реализована в основном скрипте `src/main.ts` без выделения в отдельный класс: приложение состоит из одной страницы, поэтому одного презентера достаточно.

Презентер создаёт экземпляры моделей данных, компонентов представления и класса работы с сервером, после чего подписывается на события брокера. Собственных событий презентер не генерирует.

События представлений приводят к вызову методов моделей данных. Модели при изменении данных генерируют собственные события, и уже их обработка вызывает перерисовку компонентов.

Все компоненты представления, кроме карточек каталога и корзины, создаются однократно при запуске приложения и переиспользуются. Карточки каталога и корзины создаются заново при изменении соответствующих данных.

Карточки каталога и корзины получают в конструктор функцию-обработчик без параметров. При создании карточки презентер захватывает идентификатор товара в замыкание, а внутри обработчика генерирует событие с этим идентификатором.

Презентер также отвечает за подготовку данных для компонентов: надпись на кнопке подробной карточки и её доступность вычисляются функцией `getButtonLabel`.
